# jp-breach-records

日本の企業・自治体・団体が**自ら公表した**情報漏えい・不正アクセスの記録です。2026年1月以降の公表を、公表文ごとに1行にしています。CSV と JSON で配布します。

- 行数: 568（2026-10-28 時点）
- 画面で見る: https://radineer.asia/cyber/ （毎日6回更新。各行の `url` から、出典と根拠を確認できます）
- 作った人: 合同会社Radineer（サイバー防衛相談室）

## ファイル

- `data/records.csv`（UTF-8・BOM付き。Excel でそのまま開けます。複数の値は ` / ` で区切っています）
- `data/records.json`

## 項目

| 項目 | 内容 |
|---|---|
| id | 台帳の記録ID |
| org | 公表した組織（／の後ろは、事故が起きたサービスや委託先など） |
| published / latest | 初報の公表日 / 収録した資料の最新の公表日 |
| events | 事象の種類（不正アクセス・ランサムウェア・誤送信・誤送付・紛失・盗難・内部不正・誤表示） |
| status | 公表文の確認状況（流出確認・流出のおそれ・調査中・閲覧可能だった） |
| nature / where / how / device | 事象の性質 / 起きた側（自社・委託先や外部サービス・子会社）/ 入り方 / 入口の機器。公表文に書かれていなければ「記載を確認できず」 |
| info_types | 公表された対象の情報の種類 |
| counts | 公表文に書かれた件数・人数（項目名・値・確認かおそれか）。合計ではありません |
| sources | 出典（公表文の URL） |
| review | 分類の確認状況 |
| url | 台帳の該当ページ |

## 数え方と限界

- 1行は「1つの組織が出した公表」です。事案（インシデント）の単位ではありません。1つのサービスの事故を、利用していた多くの組織がそれぞれ公表すると、その数だけ行があります。
- 対象は、組織が自らウェブサイトや適時開示で出した公表文です。報道だけの事案は入れていません。網羅的な統計ではありません。
- 2026年10月から、適時開示とニュースの見出しを手がかりに公表文を探す方法を加えました。9月以前とは集め方が違うため、月ごとの行数の増減を比べることはできません。
- 種類・起きた側・入り方は、公表文の記述を AI で分類したものです。人による全件確認はしていません。
- 日付は初報、件数は続報から取っていることがあります。件数がどの版の公表文から来たかは、出典を確認してください。
- 同じ組織が書き方の違う名前で2行入っている記録が少しあります。順に直しています。
- 公表文の本文や引用は含めていません。内容は出典で確認してください。
